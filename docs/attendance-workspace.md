# الحضور والانصراف — التشغيل والاختبار

## واجهة الموظف

- `/employee-self-service`: الشعار واسم البوابة في الأعلى، والخروج بأيقونة ذات تسمية وصول. بيانات الموظف والتاريخ داخل البطاقة الحمراء.
- التبويبات: الحضور والانصراف، الإجازات، القرارات والتعاميم، أجهزتي، الدعم الفني. طلب الاستئذان داخل الإجازات.
- يظهر موقع البصمة المسند ونطاقه، ثم أدوات التسجيل. يجب على الموارد البشرية إسناد الموقع؛ موقع السكن النصي ليس تصريحًا للبصمة.
- لا توجد قائمة يختار منها الموظف الفترة؛ يحددها الخادم تلقائيًا. عند عدم إسناد موقع نشط تتعطل أزرار البصمة مع رسالة مراجعة الموارد البشرية، بدل طلب الموقع دون إمكانية قبول البصمة.
- تحديد الموقع ينتظر تحسن القراءة الأولى التقريبية حتى 35 ثانية، ويطلب دقة 50 مترًا أو أفضل دون تخفيف حدود النطاق. تميز الرسائل رفض الإذن، وضعف الدقة، وانتهاء المهلة، وتظهر مساعدة مختصرة عند التعذر.
- جدول سطح المكتب يستعمل عرض الصفحة كاملًا، وأحدث الأيام أولًا، وتواريخ رقمية معزولة باتجاه يسار–يمين وأوقات مختصرة بتوقيت الرياض. بطاقات الحضور على الجوال مستقلة ولم يتغير ترتيبها أو تنسيقها. تبقى المقاييس التاريخية غير الموثقة «غير متاح».
- نموذج طلب الإجراء في القرارات والتعاميم بحقول منفصلة: عمودان على سطح المكتب وعمود واحد على الجوال. تواريخ المستندات وبصمات النسخ والتواريخ التقنية معزولة اتجاهيًا، دون تعديل محتوى الإقرار أو إجراءات الحفظ والاعتماد.
- «معالجة التقصير»: سبب إلزامي، ملف PDF/PNG/JPEG اختياري حتى 5 ميغابايت. الطلب المعلق أو المرفوض لا يمحو التقصير.

## الموارد البشرية

- `/hr/login` ثم `/hr/attendance-monitor`: عرض يومي أولًا، اليوم/أمس/تاريخ محدد، بحث وحالة وموقع، وجدول/بطاقات حسب الشاشة. مؤشرات الأعداد تحسب الموظفين دون مضاعفة أصحاب الفترتين.
- الغياب النهائي لا يحتسب قبل انتهاء الفترة. إعداد بلا نهاية دوام لا يكفي لإثبات غياب أو نقص خروج.
- قائمة المعالجة تقبل الاعتماد أو الرفض مع سبب رفض. الاعتماد الكلي للفترة متاح بعد انتهائها، حتى لا يغطي تقصيرًا مستقبليًا غير مشاهد.
- الاعتماد يعالج الحالة ودقائقها الفعلية ولا يغيّر أوقات البصمات. محفوظات القرار والمعالجة والمرفق باقية. المرفقات خاصة بصاحبها والمالك/الموارد البشرية، وليست لمجرد امتلاك صلاحية IT.
- `/hr/employees`: إدارة الأقسام وإسناد موقع البصمة وخيار الجدول، مع الاحتفاظ بالمسميات الوظيفية الموجودة. يمنع حذف قسم مرتبط بأي موظف، نشط أو غير نشط.
- `/hr/attendance-monitor?tab=zones`: بحث Google Places أو تحديد مركز بالنقر، نطاق عددي ودائرة تلقائية، وخيارات جداول متعددة للموقع. كل خيار فترة واحدة أو فترتان دون تداخل؛ لا يدمج النظام جميع خيارات الموقع في دوام الموظف.
- لا يمكن حذف جدول مسند قبل نقل موظفيه، ولا حذف موقع ذي روابط. تعديلات التكوين لا تعيد تفسير جدول يوم سبق تثبيته.

## التحقق المنفذ في التطوير

- 221 اختبارًا آليًا، بما فيها اتصال حقيقي بقاعدة التطوير لحفظ الجدول داخل معاملة ترجع دون حفظ، وعزل جلسات الموظفين، والتقصير والاعتماد المكرر، وانتظار تحسن دقة الموقع وتنظيف مراقب الموقع ورسائل رفض الإذن والمهلة.
- متصفح جوال وسطح مكتب: دخول تطوير دون SMS، رفع مرفق، رفض ثم إعادة تقديم واعتماد مع بقاء الأوقات، حضور GPS داخل الموقع، الأقسام، نموذج الموظف، Google Maps/Places، وفترتان مع حذف أي منهما.
- فحص HTTP على موظف مؤقت فقط: انصراف GPS، رفض موقع خارج النطاق، إضافة قسم وإسناده ومنع حذفه ثم إفراغه وحذفه، خيارات دوام أحادي/مزدوج ومطابقة الإسناد، وحماية الحذف. بقاء الصيانة وحجب ERP وعزل المالك والموظف.
- بيانات الاختبار تحمل بادئة `ATT-UI-`، وتُنظّف مع الجلسات والمرفقات والإشعارات. لا تستخدم بيانات الموظف التجريبي اليدوي للاختبارات الآلية.

أوامر إعادة الاختبار (تطوير فقط، وملفات الاعتماد المؤقتة لا تُحفظ في المستودع):

```sh
npm test -- --maxWorkers=2
NODE_ENV=development npx tsx scripts/attendance-ui-fixture.ts create <unique-tag>
# احفظ خرج الأمر السابق محليًا بملف مؤقت، ولا تنشره.
# أتم رحلة المعالجة حتى الاعتماد وبصمة حضور اليوم على هذا الموظف المؤقت قبل الفحص التالي.
NODE_ENV=development npx tsx scripts/check-attendance-workspace.ts <temporary-fixture-json>
NODE_ENV=development npx tsx scripts/attendance-ui-fixture.ts cleanup <unique-tag>
npm run build
node scripts/smoke-production.mjs
```

فحص الحزمة يعمل على مخطط تطوير مؤقت مع تعطيل الشبكة الخارجية، وليس على الإنتاج. ما زالت بالمشروع 41 مشكلة أنواع قديمة خارج هذه التغييرات؛ لا توجد تشخيصات في ملفات هذه الميزة. يظهر تحذير ترحيل Google Places القديم رغم عمل البحث، ويمكن تحديثه مستقلًا.
