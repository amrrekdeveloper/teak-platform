# تنظيم الموارد البشرية في تيك — مقارنة ZenHR وخطة التطوير

## ضوابط التنفيذ
- صور ZenHR والملف المقترح مراجع لفهم أسلوب العمل، وليست قائمة يجب نسخها كاملة.
- الحفاظ على نموذج الاستئذان الحالي وطباعته. الإضافات داخله: الموافقات والمرفق فقط.
- الاحتفاظ بقاعدة البيانات ومسارات الطلبات الأصلية، وعدم إنشاء نسخة ثانية من الطلب في مركز الموافقات.
- لا حذف لسجلات الحضور أو الإجازات الحقيقية، ولا إعادة اعتماد السجلات القديمة تلقائيًا.
- العربية والإنجليزية، واتجاه القراءة، والوضعان النهاري والليلي، والجوال وسطح المكتب.

## المقارنة والقرار
| المرجع والاحتياج | وضع تيك والقرار |
|---|---|
| لوحة معلومات قابلة للعمل | مدخل موارد بشرية يعرض أعداد الطلبات والإجراءات وبيانات الربط الناقصة، مع روابط إلى الأنظمة الفعلية. |
| الموافقات والطلبات | مركز موحد للإجازات والاستئذانات، ببحث وفلاتر وتصفح صفحات. تفتح التفاصيل والقرارات الأصلية؛ لا قاعدة طلبات موازية. |
| تنظيم القائمة | فصل الصفحة الرئيسية عن الصفحات الفرعية، وتمييز الصفحة النشطة فقط؛ الاحتفاظ بالروابط السابقة. |
| تهيئة النظام | مدخل منظم للإعدادات الحالية: الدوام والمواقع والورديات والتعيينات والصلاحيات والإجراءات، مع إعداد مسار الإجازة والاستئذان. |
| سلسلة الموافقات | مدير مباشر ثم الموارد البشرية، أو الموارد البشرية مباشرة، حسب النوع. يمكن اشتراط مدير ذي حساب نشط. لا اعتماد تلقائي جديد. |
| تغيير المدير أو الإعدادات | الطلب الجديد يحفظ مساره عند تقديمه. تغييرات الإعدادات لا تعيد توجيه الطلبات الجارية. السجلات السابقة تبقى بمسارها السابق. |
| المدير غير المرتبط | توضيح خيار التحويل المباشر للموارد البشرية عند عدم اشتراط المدير. التدخل في مرحلة مدير قائم يظل صريحًا ومسببًا. |
| مرفقات الاستئذان والإجازة | ملفات خاصة، PDF أو JPEG أو PNG، حتى خمسة ملفات، بحد خمسة ميغابايت لكل ملف. الاطلاع للموظف صاحب الطلب والموارد البشرية؛ لا صلاحية طبية تلقائية للمدير أو الدعم التقني. |
| التقارير الطبية | تبقى بنظامها وحمايتها الأصليين؛ المرفق العام لا يحل محل التقرير الطبي المطلوب للإجازة المرضية. |
| الرفض والتوضيح | تبقى حالات الرفض والتوضيح والتاريخ محفوظة، ولا يُحوّل الرفض إلى اعتماد أو تُحذف البصمات. |
| بطء التحميل | تجميع الاستعلامات المستقلة للطلبات، وإعادة استخدام إعدادات الدوام المشتركة عند إعداد المراقبة؛ المركز الجديد لا يحمل جميع السجلات دفعة واحدة. |
| كثرة قوائم ZenHR | لا إنشاء صفحات مالية أو إعدادات وهمية لمجرد ظهورها بالصور. الربط بالمحركات المالية والإجرائية الحالية، والتوسع بقواعد عمل معتمدة. |

## ما يحتاج بيانات أو قرارًا إداريًا
- ربط الموظفين بمديريهم الفعليين وحساباتهم النشطة؛ لا تخمين للمدير أو إنشاء حسابات لأشخاص بالنيابة عنهم.
- مراجعة الوثائق وتواريخ انتهائها وبيانات العقود حتى تكون تنبيهات الامتثال ذات معنى.
- قوالب موافقات أكثر من مرحلتين، أو شروط خاصة بالأقسام، أو تفويضات مؤقتة: توسعة مستقلة تحفظ مسارات الطلبات القائمة وتحتاج تحديد المسؤوليات الفعلية أولًا.
- لا تغيير تلقائي لمسير رواتب مدفوع، أو أرصدة افتتاحية مفترضة، أو إصلاح هويات وأسماء تخميني.

## انتقال آمن إلى الإنتاج
1. لا تشغيل لترحيلات إنتاج مخصصة عند بدء الخادم أو في أمر البناء.
2. تغيير المخطط الإضافي: جدول إعدادات صغير؛ بيانات الموافقات والمرفقات تُحفظ في حقول الطلب الأصلية.
3. الإعداد الافتراضي عند خلو الجدول: مدير بحساب نشط عند وجوده، ثم الموارد البشرية؛ وعند تعذر المدير يصل الطلب الجديد للموارد البشرية للمراجعة، لا للاعتماد التلقائي. لا يتغير مسار الطلبات السابقة.
4. إعادة النشر تطبق تغييرات المخطط عبر مسار النشر المعتاد. لا تختَر استبدال بيانات الإنتاج ببيانات التطوير.
5. بعد النشر: افتح الرئيسية ومركز الطلبات والإعدادات بحساب الموارد البشرية، وافحص طلبًا تجريبيًا مستقلًا، دون إعادة معالجة الطلبات الحقيقية القديمة.
